# Walkthrough: FR-003 Replace ORPHAN_CHECK_TYPES with root Metadata (v1)

## Files Changed

- [src/model/types.ts](../../src/model/types.ts) — added `root?: boolean` to `DocTypeDefinition` and `DocNode` (T1)
- [src/crawler/crawler.ts](../../src/crawler/crawler.ts) — copies `def.root` onto each crawled `DocNode` (T2)
- [src/crawler/graph.ts](../../src/crawler/graph.ts) — removed `ORPHAN_CHECK_TYPES`; `computeProblems` now
  orphan-checks every node unless `node.root === true` (T3)
- [src/crawler/docTypes.ts](../../src/crawler/docTypes.ts) — added `root: true` to `fr-plan`, `fr-tasks`,
  `fr-walkthrough`, `instructions`, `skill` in `DEFAULT_DOC_TYPES` to preserve current behavior (T4)
- [src/scaffold/scaffold.ts](../../src/scaffold/scaffold.ts) — added `root: true` to the `mission`, `sdd`,
  `epic` entries generated by `buildSpecmeshYml` (T5)

## Build/Test Results

- `get_errors` on all five changed files: no errors.
- `npx tsc --noEmit -p tsconfig.json`: clean, no output/errors.
- No automated test suite exists in this repo for `computeProblems`/orphan detection; verification is by
  compile-check and code review (matches existing project practice).

## Follow-ups / Known Gaps

- Custom `.specmesh.yml` `track:` lists that declare doc types without a `root` flag will now have those types
  orphan-checked by default (previously never checked) — this is the intended, documented effect of this FR
  (see spec's Assumptions), not a regression.
- Named/swappable doc-type-set ("pattern pack") support, pattern-driven `scaffold.ts`, and custom pack folders
  remain out of scope — future FRs under EPIC-002.
